# ติดตั้ง Code.gs สำหรับ V9.5 — ใช้ตารางเดิม 4 คอลัมน์

ปรับจาก doPost เดิมที่หมอโยส่งมา ซึ่งบันทึก timestamp, name, dob, note ตามลำดับ
ใช้กับ HTML V9.5 ฉบับยืนยันบันทึกที่ส่งให้ล่าสุดได้โดยไม่เปลี่ยนรูปแบบคำขอ
โค้ดพร้อมติดตั้ง แต่ยังไม่ได้ Deploy หรือทดสอบกับ Google Sheet จริง

## 1. เตรียมแท็บเดิม

สำรอง Sheet และ Code.gs เดิมก่อน จากนั้นเปิดแท็บที่เคยรับข้อมูล
แถว 1 ต้องเป็นหัวตาราง ถ้าข้อมูลเริ่มตั้งแต่แถว 1 ให้แทรกแถวหัวตารางก่อน ห้ามพิมพ์ทับรายการแรก
คงชื่อหัวคอลัมน์ A–D ตามเดิมได้ แต่ข้อมูลต้องเรียงตามนี้:

| ช่อง | ข้อมูล | สิ่งที่ต้องทำ |
|---|---|---|
| A | เวลาเดิมจากหน้าเว็บ | คงไว้ |
| B | ชื่อ | คงไว้ |
| C | วันเกิด | คงไว้ |
| D | หมายเหตุ | คงไว้ |
| E1 | request_id | เพิ่มหัวคอลัมน์นี้ |
| F1 | saved_at | เพิ่มหัวคอลัมน์นี้ |

E และ F ต้องยังไม่มีข้อมูลหรือสูตรอื่นใช้งาน หากมี อย่าทับ ให้แจ้งเพื่อปรับตำแหน่งคอลัมน์ก่อน
รายการเก่าปล่อย E–F ว่างได้ ไม่ต้องย้ายหรือเติมรหัสย้อนหลัง
รายการใหม่จะเก็บเวลา A และ F เป็นข้อความ ISO UTC (ลงท้าย Z) เพื่อเทียบข้อมูลได้แน่นอน

คัดลอกบรรทัดนี้แล้ววางที่ E1 เพื่อเติมหัวคอลัมน์ 2 ช่อง:

```text
request_id	saved_at
```

## 2. ใส่โค้ดและตั้งค่าปลายทาง

1. เปิด Apps Script โปรเจกต์เดิมที่ใช้กับปุ่มบันทึก
2. แทนที่ Code.gs เดิมที่ส่งมาในแชท ด้วยเนื้อหา Code.gs ในชุดนี้ แล้วกดบันทึก
3. ไปที่ Project Settings (รูปเฟือง) → Script Properties → Add script property
4. เพิ่ม 2 ค่าแล้วบันทึก:

| Property | Value |
|---|---|
| SPREADSHEET_ID | ID ของไฟล์ Google Sheet เป้าหมาย |
| SHEET_NAME | ชื่อแท็บด้านล่างของ Sheet แบบตรงตัว รวมช่องว่าง |

ตัวอย่าง URL ของ Sheet: `https://docs.google.com/spreadsheets/d/ABC123/edit#gid=0`
ในตัวอย่างนี้ SPREADSHEET_ID คือ `ABC123` ไม่ใช่เลข gid และไม่ใช่ URL เต็ม
SHEET_NAME คือชื่อแท็บ เช่น `ข้อมูลลูกค้า` ไม่ใช่ชื่อไฟล์ด้านบน
ไม่ต้องส่งรหัสผ่านหรือ token ให้ใคร

โค้ดนี้ระบุไฟล์และชื่อแท็บแน่นอน ไม่ใช้ active sheet ขณะรับคำขอ
ถ้าตั้งชื่อผิดจะหยุด ไม่สร้างแท็บใหม่แทนโดยเงียบ ๆ
ไม่ต้องกด Run ที่ doPost เพราะการกด Run ไม่มีข้อมูลคำขอ e

## 3. อัปเดต deployment เดิม

Deploy → Manage deployments → เลือก Web app เดิม → รูปดินสอ Edit → Version: New version → Deploy
คงค่า Execute as และ Who has access เดิมไว้ พร้อมอนุญาตสิทธิ์ที่ Google ร้องขอสำหรับการแก้ไขนี้
การแก้ deployment เดิมให้ใช้เวอร์ชันใหม่คง URL เดิมได้ จึงไม่ต้องแก้ HTML
หากสร้าง deployment ใหม่จน URL เปลี่ยน ต้องแก้ DATABASE_URL ใน HTML ให้ตรง URL /exec ใหม่

อ้างอิง [Google: Edit a versioned deployment](https://developers.google.com/apps-script/concepts/deployments#edit_a_versioned_deployment)

## 4. ตรวจความพร้อมและทดลองบันทึก

เปิด URL ของ Web app ซึ่งลงท้าย /exec แล้วเติม `?action=health`
ถ้าตั้งค่าถูกและอ่านแท็บได้ ควรเห็น:

```json
{"protocol":"promyan-save-v1","ok":true,"ready":true}
```

นี่ตรวจเฉพาะการเข้าถึงแท็บและหัวคอลัมน์ ยังไม่พิสูจน์สิทธิ์เขียนหรือการอ่านคำตอบจากหน้าเว็บข้ามโดเมน
จากนั้นใช้ HTML V9.5 ฉบับล่าสุดเพื่อทดสอบ:

| ขั้นตอน | ผลที่ต้องตรวจ |
|---|---|
| สร้างแผนผัง กรอกชื่อ `ทดสอบระบบ V9.5` และหมายเหตุ `ทดสอบการยืนยัน` แล้วกดบันทึก | Sheet เพิ่มหนึ่งแถว A–F; เว็บแสดงคำยืนยันพร้อมเลขแถวและรหัสรายการ |
| เปรียบเทียบเว็บกับ Sheet | รหัสตรงกับคอลัมน์ E และเลขแถวตรงกัน |
| กดบันทึกอีกครั้งโดยไม่เปลี่ยนข้อมูล | แจ้งว่ารายการนี้มีแล้ว และจำนวนแถวไม่เพิ่ม |
| รีโหลดแท็บเดิม สร้างข้อมูลเดิมแล้วลองส่งซ้ำ | ใช้รหัสเดิมถ้า sessionStorage ยังอยู่ และไม่เพิ่มแถวซ้ำ |

ส่งภาพข้อความยืนยันบนเว็บกับแถวทดสอบ E–F เพื่อช่วยตรวจผลได้ โดยไม่ต้องส่งข้อมูลลูกค้ารายอื่น

## วิธีอ่านปัญหา

| รหัส/อาการ | ตรวจอะไร |
|---|---|
| NOT_CONFIGURED | Script Properties ขาด SPREADSHEET_ID หรือ SHEET_NAME |
| SHEET_NOT_FOUND | ชื่อแท็บไม่ตรง |
| SCHEMA_MISMATCH | E1/F1 ต้องเป็น request_id/saved_at ตรงตัว |
| NOT_READY | ID ผิดหรือบัญชีที่รันไม่มีสิทธิ์อ่าน Sheet |
| BUSY | มีคำขออื่นกำลังบันทึก รอสักครู่แล้วลองซ้ำในแท็บเดิม |
| SAVE_NOT_CONFIRMED / READBACK_FAILED | ยังไม่ยืนยันสำเร็จ ตรวจแถวใน Sheet ก่อนส่งซ้ำ |
| health เปิดได้ แต่หน้าเว็บอ่านคำตอบไม่ได้ | ต้องตรวจ CORS/การลงชื่อเข้าใช้/สิทธิ์ deployment จากหน้าเว็บจริง |

หากคำตอบหายหลังส่ง ข้อมูลอาจเขียนแล้ว ให้ลองซ้ำในแท็บเดิมเพื่อใช้ request_id เดิม
ห้ามแก้ด้วย no-cors แล้วถือว่าบันทึกสำเร็จ หรือปิดระบบความปลอดภัยของเบราว์เซอร์

## ขอบเขตการรับรอง

- ใช้ ScriptLock ป้องกันคำขอจากสคริปต์เดียวกันชนกัน ค้น request_id ก่อนเพิ่มแถว
- เขียนข้อมูลแล้ว flush และอ่านทั้ง 6 ช่องกลับมาเทียบก่อนส่ง verified=true
- ตอบ JSON ที่หน้าเว็บ V9.5 ตรวจสอบได้ ไม่ตอบเพียง Success
- GET ไม่คืนรายชื่อ วันเกิด หรือรายการบันทึก
- กันซ้ำได้เมื่อส่ง request_id เดิม ไม่ครอบคลุมอีกแท็บ/อีกเครื่อง/ล้าง sessionStorage หรือข้อมูลเก่าที่ไม่มีรหัส
- การแก้/ลบรหัสใน E หรือการเขียนด้วยสคริปต์อื่นอยู่นอกการควบคุมของ ScriptLock นี้
- ผ่านชุดทดสอบโค้ดและสูตร 20/20 โดยจำลองบริการ Google; ยังไม่ผ่านการตรวจรับบนบัญชีจริง
- HTML และผล UI 54/54 เป็นผลรอบก่อน การแก้รอบนี้เปลี่ยนเฉพาะ backend/ชุดทดสอบ/คู่มือ ไม่ได้รัน UI ซ้ำ
